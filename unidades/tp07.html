25. Git y GitHub

Qué es el control de versiones y qué hace cada uno

Un proyecto cambia todo el tiempo. Un sistema de control de versiones guarda cada cambio: qué se cambió, quién lo hizo y cuándo. Así podemos volver a una versión anterior y compartir el proyecto sin mandar archivos sueltos.

  • Git En tu computadora

    Es un programa que se instala en la compu. Guarda el historial del proyecto en una carpeta oculta, .git, dentro del proyecto. Lo usamos con comandos en la terminal.

  • GitHub En la nube

    Es una página web que guarda una copia del repositorio. Desde ahí lo vemos en cualquier compu, lo compartimos y lo entregamos. Lo usamos desde el navegador.

Palabras clave

  • Repositorio (o repo): la carpeta del proyecto con todo su historial.
  • Commit: una versión guardada, con un mensaje que dice qué cambió.
  • Clonar: copiar un repositorio de GitHub a la compu.
  • Rama: una línea de trabajo. La principal se llama main.

¿Git está instalado?

En VS Code abrimos la terminal con Ctrl + ñ y escribimos git --version. En el laboratorio ya está instalado. Si en tu compu no lo está, lo instalamos como se ve en la hoja que sigue.

26. Tu cuenta y tu repositorio

Crear la cuenta de GitHub y configurar Git

Crear la cuenta

  1. 1Registrarse: en github.com, Sign up (registrarse).
  2. 2Completar: Email (tu mail), Password (contraseña) y Username (nombre de usuario). El usuario va sin espacios y aparece en el link de tus repositorios: github.com/luciagomez.
  3. 3Verificar: resolvemos la prueba que pide la página y escribimos el código que llega al mail.

El mail privado

Los repositorios son públicos y cada commit guarda el mail de quien lo hizo. Para no mostrar el nuestro, GitHub nos da un mail privado:

  1. 1Arriba a la derecha, la foto de perfil → Settings A.
  2. 2En la sección Access, Emails B.
  3. 3Tildar Keep my email addresses private (mantener privados mis mails) C.
  4. 4Copiar el mail que termina en @users.noreply.github.com D.

Configurar Git: tu nombre y tu mail

Cada commit guarda quién lo hizo. Se lo decimos a Git con git config --global: primero el nombre y después el mail. Esos dos comandos no muestran nada, solo guardan el dato. El último, sin el mail al final, muestra el que quedó guardado.

Con el mail privado (recomendado): el que copiamos de Emails.

Sin el mail privado: va el mail de la cuenta. Funciona igual, pero ese mail queda a la vista en cada commit del repositorio.

En el laboratorio

La compu se reinicia y se borra todo: configurá Git al empezar cada clase. En tu compu, alcanza con una vez.

27. El ciclo de trabajo

Del archivo al historial: status, add y commit

  1. Tu carpeta

    Creamos o cambiamos archivos en VS Code.

  2. Preparados

    git add .

    Elegimos los cambios del próximo commit. El punto quiere decir “todos”.

  3. Historial

    git commit -m "…"

    Guardamos una versión con un mensaje que dice qué cambió.

  4. GitHub

    git push

    Subimos los commits nuevos a la nube.

git status muestra en qué paso está cada cambio. Lucía creó ideas.md en su repositorio:

Qué dice git status

  • Untracked files: archivos nuevos que Git todavía no sigue. Falta git add.
  • Changes to be committed: cambios preparados. Falta git commit.
  • nothing to commit, working tree clean: no hay nada nuevo; todo está guardado.

  • Así no

    cambios · asdf · arreglo: no dicen qué cambió.

  • Así sí

    Agrego ideas.md con mi primera idea: claro, en español, dice qué cambió.

28. Subir desde la página, pull y ramas

Traer los cambios de GitHub a la compu

Subir archivos desde la página

  1. 1En el repositorio, Add file (agregar archivo) → Upload files (subir archivos) A.
  2. 2Arrastrar el archivo al recuadro, o choose your files (elegir archivos) B.
  3. 3Abajo, el mensaje C: GitHub propone Add files via upload.
  4. 4Commit changes (confirmar cambios) D.

También es un commit: lo hace GitHub. Ahora GitHub tiene un commit que la compu no tiene.

Traer los cambios: git pull

Lucía subió logo.png desde la página. Para tenerlo en la compu, en la terminal de VS Code escribe git pull: Git trae los commits nuevos de GitHub y actualiza la carpeta.

Recomendación: antes de empezar a trabajar, git pull. Así la compu queda igual que GitHub.

28. Subir desde la página, pull y ramas (sigue)

Las ramas y los comandos del TP · sigue

Una rama es una línea de trabajo aparte: probamos cambios sin tocar main. Cuando están listos, los unimos a main con git merge. En este TP la práctica se hace toda en main: las ramas las vas a usar en equipo, en el TP9.

Los comandos de este TP

Los comandos de Git de este TP y qué hace cada uno
git --versionMuestra la versión de Git: así sabemos si está instalado.
git config --globalGuarda nuestro nombre y nuestro mail.
git initConvierte una carpeta en un repositorio.
git cloneCopia un repositorio de GitHub a la compu.
git statusMuestra qué cambió y qué está preparado.
git add .Prepara todos los cambios para el próximo commit.
git commit -m "…"Guarda una versión con un mensaje.
git pushSube los commits nuevos a GitHub.
git pullTrae los commits nuevos de GitHub a la compu.
git logMuestra el historial de commits.
git branchCrea una rama o, sin nombre, muestra las que hay.
git switchNos pasa a otra rama.
git mergeUne a la rama en la que estamos los commits de otra.

Idea clave: git pull trae a la compu lo que cambió en GitHub. Las ramas sirven para probar cambios sin tocar main.

Un poco más sobre cada lámina

Lámina 25

La carpeta .git y otras plataformas

Git guarda todo el historial en la carpeta .git, dentro del repositorio. Está oculta: en el Explorador de Windows 11 se ve con Ver → Mostrar → Elementos ocultos.

Con git log vemos ese historial sin abrir la carpeta.

No la toques

Si se borra o se cambia a mano la carpeta .git, se pierde el historial.

No solo GitHub

GitLab y Bitbucket también guardan repositorios de Git en la nube. Los comandos son los mismos.

Lámina 26

Público o privado, y qué no subir

  • Público: cualquiera lo ve con el link. Es el que usamos para entregar.
  • Privado: solo lo ven quien lo creó y las personas que invite como colaboradores (Settings → Collaborators).
  • La visibilidad se puede cambiar después, en Settings del repositorio.

Nunca subas

  • Contraseñas ni claves.
  • Datos personales: teléfono, dirección, DNI.
  • La carpeta node_modules (TP6): se regenera con npm install.

Lámina 27

Markdown: el formato de los .md

README.md, ideas.md y comandos.md están escritos en Markdown: texto común con algunos símbolos. GitHub lo muestra con formato.
