18. El ambiente de desarrollo

Editor vs. IDE y tres filosofías

¿Qué pasa cuando no configuramos nada?

  • Los errores aparecen recién cuando ejecutamos el código, no antes.
  • El código queda desprolijo: indentaciones distintas, estilos mezclados.
  • El clásico: “en mi máquina funciona” — y en la del compañero, no.
  • No hay forma de inspeccionar qué hace el programa paso a paso.

¿Qué es un ambiente de desarrollo? Es el conjunto de herramientas, configuraciones y convenciones que usamos para escribir, probar y ejecutar código de forma ordenada y profesional.

¿Y un ambiente de testing? Es un entorno separado donde probamos que el código funciona correctamente antes de “mandarlo a producción”. Evita que los errores lleguen al usuario final.

Editor vs. IDE: ¿cuál es la diferencia?

No todas las herramientas son iguales. Dependiendo de lo que necesitemos, elegimos un nivel distinto de soporte. Acá va la tabla completa:

Niveles de herramientas: editor de código simple, editor extensible e IDE completo, con un ejemplo de cada uno y lo que aporta
NivelEjemplo¿Qué aporta?
Editor de código simpleNotepad++, Sublime TextResaltado de sintaxis básico, edición rápida. Sin inteligencia del lenguaje.

En este TP usamos VS Code: el punto medio ideal entre flexibilidad y potencia para aprender.

Tres filosofías para elegir tu herramienta

No hay una sola forma de trabajar. Cada herramienta refleja una forma de pensar el desarrollo:

  • VS Code “Lo configuro yo”

    Editor extensible y liviano. Arranca simple y crecés con él: agregás extensiones según lo que necesitás. Ideal para aprender porque entendés cada pieza que sumás.

    Control total. Curva de aprendizaje gradual.

  • Antigravity (Google) “El que vuela solo”

    IDE de escritorio desarrollado por Google, basado en VS Code. Está centrado en agentes de IA (Gemini) que planifican y ejecutan tareas.

    Agentes de IA integrados.

  • WebStorm / PyCharm “Ya viene resuelto”

    IDEs completos de JetBrains, atados a un lenguaje específico. Todo configurado desde el primer momento: análisis, refactor, testing. Sin tocar nada.

    Máxima integración. Menos decisiones.

Idea clave: un buen ambiente de desarrollo es como tener el taller ordenado antes de empezar a construir algo.

19. Anatomía de VS Code

Las zonas del editor y las extensiones

VS Code está dividido en zonas bien definidas. Conocerlas te ayuda a moverte rápido y no perder tiempo buscando dónde está cada cosa:

Las seis zonas

  1. 1Explorador de archivos. Panel izquierdo. Muestra la estructura de carpetas y archivos del proyecto abierto.
  2. 2Área de edición. El centro de la pantalla. Podés abrir varios archivos en pestañas o en paneles divididos.
  3. 3Terminal integrada. Abrís con Ctrl + ñ. Ejecutás comandos node, npm y git sin salir del editor. Ctrl + J muestra u oculta el panel.
  4. 4Barra de extensiones. Ícono de cuadradito en la barra lateral. Desde acá instalás y gestionás extensiones del Marketplace.
  5. 5Paleta de comandos. Ctrl + Shift + P: el acceso directo más importante. Ejecutá cualquier acción del editor escribiendo su nombre.
  6. 6Barra de estado inferior. Muestra el lenguaje activo, la rama de Git, errores y advertencias del archivo actual.

Extensiones: el superpoder de VS Code

  • ¿Qué son las extensiones?

    Son complementos que agregan funcionalidades nuevas al editor base. VS Code viene “vacío a propósito”: vos decidís qué herramientas necesitás y las instalás desde el Marketplace (el repositorio oficial de extensiones).

  • ¿Cómo se instalan?

    Desde la barra lateral → ícono de extensiones 4 → buscás el nombre → Install (en español, Instalar). También podés instalarlas desde la paleta de comandos o la web del Marketplace.

    Las extensiones se guardan en tu perfil de VS Code. Si sincronizás con una cuenta, las tenés en cualquier máquina.

Extensiones esenciales para JavaScript

  • ESLint

    Muestra errores y malas prácticas en tiempo real mientras escribís.

  • Prettier

    Formatea el código automáticamente al guardar el archivo.

  • Live Server

    Lanza un servidor local en el navegador que se actualiza automáticamente cada vez que guardás un archivo HTML, CSS o JS. Ideal para ver cambios en tiempo real sin recargar manualmente.

Más extensiones (JavaScript snippets, GitLens y Live Share), en “Para profundizar”.

Idea clave: VS Code es un editor extensible: vos elegís cada pieza y entendés para qué sirve.

20. Linter vs. formateador

ESLint y Prettier

Linter: el revisor de código

¿Qué hace un linter? Un linter analiza tu código antes de ejecutarlo y te señala errores, malas prácticas y código sospechoso. Es como tener un corrector ortográfico, pero para programación.

ESLint para JavaScript. El linter más usado en el ecosistema JS. Se configura con reglas (podés usar un conjunto predefinido como eslint:recommended) y subraya las líneas problemáticas directamente en el editor.

¿Qué detecta?

  • Variables declaradas pero nunca usadas.
  • Uso de var en lugar de let o const.
  • Comparaciones con == en lugar de ===.

eslint:recommended trae no-unused-vars; no-var y eqeqeq se activan aparte (ver “Para profundizar”). El punto y coma no lo revisa ESLint: lo pone Prettier.

Formateador: el que acomoda el desorden

¿Qué hace un formateador? Un formateador reacomoda el estilo del código automáticamente sin cambiar su lógica ni su funcionamiento. No te dice qué está mal: simplemente lo deja prolijo según las reglas del equipo.

Prettier. El formateador más popular para JavaScript, TypeScript, HTML y CSS. Se integra con VS Code y puede configurarse para que formatee cada vez que guardás el archivo (opción Format On Save).

¿Por qué importa el estilo? En un equipo, cada programador tiene sus costumbres. Prettier las unifica para que el código siempre luzca igual, sin importar quién lo escribió. Menos discusiones, más legibilidad.

Prettier agregó espacios, indentación y punto y coma automáticamente, sin cambiar la lógica del código.

Linter vs. formateador: no son lo mismo

Se usan juntos, pero cumplen roles distintos. Confundirlos es uno de los errores más comunes al configurar un proyecto:

Linter (ESLint) y formateador (Prettier): qué revisa, qué corrige, cuándo actúa, si cambia la lógica y si son excluyentes
CaracterísticaLinter (ESLint)Formateador (Prettier)
¿Qué revisa?Errores lógicos, malas prácticas, variables sin usarEspacios, indentación, punto y coma, comillas
¿Qué corrige?Señala el problema. Algunos los corrige automáticamente.Corrige el estilo completo automáticamente al guardar
¿Cuándo actúa?Mientras escribís (en tiempo real en el editor)Al guardar el archivo (o al ejecutar el comando)
¿Cambia la lógica?No cambia el código, solo avisaNo cambia la lógica, solo el estilo visual
¿Son excluyentes?No. Se usan juntos y se complementan perfectamente.

Idea clave: ESLint cuida la calidad del código. Prettier cuida la apariencia. Necesitás los dos.

21. El depurador

Breakpoints, paso a paso y variables

El depurador (en inglés, debugger) pausa el programa en la línea que elegimos. Ahí podemos ver el valor de cada variable y avanzar de a una instrucción. Con console.log solo vemos lo que decidimos imprimir, y al final; con el depurador vemos todo, en el momento en que pasa.

Paso a paso

  1. 1Poner un breakpoint (punto de interrupción): clic a la izquierda del número de línea. Aparece un punto rojo A.
  2. 2Iniciar: F5 y elegimos Node.js. También desde el panel Ejecución y depuración (Run and Debug), con Ctrl + Shift + D.
  3. 3El programa se detiene en el breakpoint. La línea en amarillo B todavía no se ejecutó.
  4. 4Mirar las variables en el panel Variables C.
  5. 5Avanzar con la barra de depuración D:

22. Node.js

El puente desde el pseudocódigo

¿Qué es Node.js?

Node.js es el entorno que permite ejecutar JavaScript fuera del navegador, directamente en la terminal de tu computadora. Antes de Node, JavaScript solo podía correr dentro de un browser. Con Node, JS se convirtió en un lenguaje de propósito general.

¿Cómo se ejecuta?

Con node archivo.js. Ese comando lee tu archivo JavaScript y lo ejecuta en la terminal, igual que cuando ejecutaban pseudocódigo en el intérprete.

23. npm: el gestor de paquetes

figlet, package.json y node_modules

El problema planteado

“Quiero que mi saludo se imprima como un cartel gigante de letras ASCII en la terminal. ¿Lo programo yo desde cero?”

No. Alguien ya lo hizo, lo empaquetó y lo publicó para que cualquiera lo use. Eso es npm (Node Package Manager): el repositorio más grande del mundo con más de 2 millones de paquetes listos para usar.

npm viene incluido con Node.js. Cuando instalás Node, npm ya está disponible en la terminal.

JSON no es código que se ejecuta. Es solo un archivo de configuración que otros programas leen para saber cómo comportarse.

package.json: el manifiesto del proyecto

Usa el formato JSON (ver “Para profundizar”) para describir el proyecto y sus dependencias. Cuando ejecutás npm install, Node lee este archivo y sabe exactamente qué paquetes descargar y cómo configurar el entorno.

¿Cómo se crea? El archivo package.json no se crea solo: hay que generarlo explícitamente al iniciar un proyecto Node.js. Se crea una sola vez, al comienzo del proyecto, ejecutando npm init -y en la carpeta raíz del proyecto (npm init, que pregunta todo paso a paso, está en “Para profundizar”). npm init -y responde todo automáticamente con valores por defecto y genera el archivo al instante. Es el comando más usado en clase porque es rápido y el archivo se puede editar después.

Actualización automática. Cada vez que instalás un paquete con npm install, el package.json se actualiza solo, agregando la nueva dependencia en la sección "dependencies".

23. npm: el gestor de paquetes (sigue)

node_modules y comandos esenciales · sigue

La carpeta node_modules

Cuando ejecutás npm install, npm descarga todos los paquetes declarados en package.json y los guarda en la carpeta node_modules. Esta carpeta puede pesar cientos de megabytes y contener miles de archivos.

  • No la editás a mano

    Nunca modifiques archivos dentro de node_modules. Se regeneran con npm install y tus cambios se pierden.

  • No la compartís

    No la mandás por WhatsApp, no la subís a GitHub. Es enorme e innecesaria: se puede regenerar.

  • Sí compartís el package.json

    Tu compañero recibe el package.json y ejecuta npm install. npm reconstruye la carpeta automáticamente.

Si alguien te manda un proyecto sin node_modules, no rompió nada. Simplemente ejecutá npm install y listo.

Comandos npm esenciales

Comandos de npm y qué hace cada uno
Comando¿Qué hace?
npm init -yCrea el package.json con valores por defecto. El -y salta todas las preguntas.

npm install -D <paquete>Instala un paquete solo para desarrollo (devDependencies). Ej.: ESLint.

Idea clave: npm + Node.js es el ecosistema que conecta tu JavaScript con el mundo real: paquetes, servidor, terminal.

24. Express y el README

Un servidor web y la documentación del proyecto

¿Y si esto se viera en el navegador?

Hasta ahora todo lo que programamos se ve en la terminal. Texto plano. Pero el desarrollo web real implica responder pedidos de navegadores, apps móviles o servicios externos. Para eso necesitamos un servidor web: un programa que está “escuchando” peticiones y responde con datos, HTML o JSON.

¿Qué es un servidor web? Es un programa que espera pedidos y responde. Como un mozo: espera que alguien pida algo, va a buscar lo que pidió y lo trae de vuelta.

Express: una dependencia más de npm

Express es un paquete npm (igual que figlet) que nos da las herramientas para crear un servidor web con JavaScript de forma sencilla. Es el framework web más popular del ecosistema Node.js.

Con ese solo comando, Express queda disponible en tu proyecto. Más abajo lo usamos para levantar un servidor real. Express no es magia nueva: es JavaScript que ya sabés, pero organizado para responder peticiones HTTP.

¿Qué pasa en cada línea?

  1. require("express"): cargamos el paquete Express que instalamos con npm. Igual que cargamos figlet antes.
  2. express(): creamos nuestra aplicación web. La variable app es el servidor.
  3. app.get("/", …): definimos qué responder cuando alguien visite la ruta "/". El método GET es el pedido estándar de un navegador.
  4. app.listen(3000): el servidor empieza a escuchar en el puerto 3000. Puerto = puerta de entrada de la computadora.

¿Para qué documentar? Un compañero tiene que poder clonar tu proyecto y dejarlo funcionando en menos de 10 minutos, leyendo solo tu documentación. Si no puede, la documentación está incompleta.

El archivo README.md es el primer archivo que alguien lee cuando entra a un repositorio. Es la “portada” de tu proyecto.

Lámina 23

¿Qué es JSON?

JSON (JavaScript Object Notation) es un formato de texto para guardar y transportar datos de forma estructurada. Lo entienden casi todos los lenguajes de programación y se basa en pares clave-valor, como un formulario: cada campo tiene un nombre y un valor.

Tres reglas

  • Claves entre comillas: cada nombre de campo va entre comillas dobles: "nombre", "edad", etc.
  • Tipos de valores: texto, número, booleano (true/false) o una lista entre [].
  • Separadores y estructura: los pares se separan con comas y todo el objeto va entre llaves {}.
